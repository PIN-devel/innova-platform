# 월간 리뷰·계좌 현금 흐름

상태: PIN-60 로컬 구현. `/motifin/review?month=YYYY-MM`은 현재 저장된 [은행·카드 비즈니스 기록](finance-business-ingestion.md)과 [사용자 보정](finance-classification.md)을 읽어 재계산한다. 합성 시안의 ‘이번 달의 결론 → 한 달의 자금 흐름 → 왜 달라졌나요 → 다음 확인’을 저장 경로에 연결한다. 새 테이블·migration은 추가하지 않는다.

## 계산과 자료 범위

은행은 원천 현지 거래일, 카드 소비는 사용자가 보정한 유효 이용일, 청구는 원천 청구월·결제일, 실제 출금은 은행 거래일로 구분한다. 원 단위 BigInt/문자열로 계산하며 카드 소비 + 카드대금 출금 합계를 새 소비로 만들지 않는다. 급여/이체 표시는 후보이며 확정 소득·투자 목적·상대 계좌 잔액을 추정하지 않는다. 은행 상세 범위는 월급·소비 통장 1개다.

은행 문서 조회기간을 선택 월로 자른 뒤 공백 없이 월 전체를 덮는지 확인한다. 월초 잔액은 해당 날짜를 포함하는 문서 기초와 이전 거래로, 월말은 해당 날짜를 포함하는 문서 기초와 그날까지의 거래로 계산한다. 월 전체 기간을 덮고 모든 거래 후 잔액 연결이 맞아야 월 현금 변화/연결 검산을 확정한다. 잔액은 자료 기준이며 현재 실시간 잔액이 아니다. 월 경계가 없는 부분 자료는 해당 경계 잔액을 null로 둔다. 중간 누락 기간이 있으면 월초/월말 근거가 있어도 전체 월 변화는 보류한다.

기간 중 거래가 없다는 문서 근거가 있는 달의 0과 자료가 없는 null을 구분한다. 새 중복/정정 후보 또는 잔액 오류가 있으면 conflict로 표시하고 경계 잔액/월 변화를 확정하지 않는다. 기존 반영된 행의 관측 유입·유출은 별도로 표시하며 이를 수정된 최종 원천값으로 오해하지 않게 한다.

카드는 현재 지원 명세만으로 전체 이용월 완전성을 증명할 수 없어 항상 unknown/missing이다. 확인된 거래의 관측 순액·원거래 건수·제외 건수·카테고리 배분과 근거를 제공한다. 해당 월 확인 거래가 없으면 관측 순액도 null이며 원천 확인 전 금액을 0으로 대체하지 않는다. 환불/배분은 PIN-59의 유효값을 그대로 사용한다.

두 달 모두 확인 거래가 있고 미확인/정정 후보가 없을 때만 ‘확보한 거래의 관측 차이’를 계산한다. 월 전체 소비 증감·정상/이상 판단은 계속 보류한다. 큰 카테고리 차이는 최대 2개까지 두 달의 근거로 연결하고 소비 행동의 원인이라고 단정하지 않는다. 전체 월 비중·자산 총액·예측은 제공하지 않는다.

## 읽기·근거·세션

`GET /api/finance/business/review?month=YYYY-MM`은 기존 approved/owner/expected actor/no-store 경계를 사용한다. Business 문서 집합을 읽고 카드 보정 snapshot과 은행 행을 모은 뒤 문서 집합이 변하지 않았는지 다시 확인한다. 변경 중이면 최대 3회 재시도 후 409이며 서로 다른 원천 집합의 합계를 조용히 섞지 않는다. 사용자 보정은 읽은 revision을 응답에 명시한다. 계산 버전·계산 시각·원천 문서 ID도 포함한다. 보존된 과거 리뷰 snapshot을 새로 만든 기능은 아니며 과거 월도 현재 보정으로 재계산한다.

은행 근거는 전체 50,000개, 카드 근거는 기존 분류 경로 10,000개 제한을 따른다. 초과 시 오류로 중단하고 조용히 일부만 합산하지 않는다. 화면 근거 목록은 100개씩 더 표시한다. 서버와 MSW는 같은 공유 pure model을 사용한다. Web은 합계를 별도로 재계산하지 않고 응답의 숫자와 연결 행을 표시한다.

Router loader가 owner/epoch/month query를 준비한다. 월/흐름/카테고리는 URL에 표현하고 거래 보정 후 해당 월 리뷰로 돌아올 수 있다. 분류 수정 성공 시 이전 월간 query를 취소·무효화하고, 다음 진입에서 재조회한다. 세션/권한 전환은 review cache를 즉시 제거한다. 최초 이용·한쪽 원천·전월 없음·늦은 청구·부분 월은 각각 정상적인 자료 부족 상태다.

청구/출금 연결 상태는 PIN-58의 근거를 사용한다. 결제일/청구월이 없으면 이번 달 청구로 추정하지 않으며 미연결을 미납으로 표시하지 않는다. 미래 예정액은 실제 소비나 통장 잔액에 선반영하지 않는다. 자금 일정/발견의 확장은 PIN-62에서 이어진다. 실행 결과·합성 dev 검증·미실행 범위는 [PIN-60](https://linear.app/pin-dev/issue/PIN-60)이 소유한다.
