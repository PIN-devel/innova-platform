# 관측 소비 분석·월별 비교

상태: PIN-61 로컬 구현. `/motifin/analysis?month=YYYY-MM`에서 현재 [사용자 분류·보정](finance-classification.md)의 동일 유효 거래를 분석한다. 원천/청구/현금 기록·전체 이용월 완전성은 [월간 리뷰](finance-monthly-review.md)의 경계를 유지한다. 새 schema/migration은 없다.

## 탐색과 계산

어디에 썼나 / 무엇이 달라졌나 / 반복·일회성 / 분류 확인의 관점과 금액·증가·감소 정렬, 카테고리 → 원천 가맹점 → 원거래를 제공한다. category/focus/sort/month는 URL에 유지한다. 거래 수정 뒤 돌아오면 그 분석 맥락에서 새 저장값을 읽는다. 원천 가맹점 표시로 묶으며 서로 다른 실제 사업자를 안정 ID로 식별한다는 뜻은 아니다. 보정된 거래명은 개별 거래 표시로 사용한다.

금액은 원 단위 BigInt다. 순액은 유효 배분의 합계이며 구매·환불·확인한 수수료를 구분한다. 구매 건수는 배분이 있는 원구매 수, 환불 건수는 음수 원천 기록 수다. 분할행을 원거래 수에 더하지 않는다. 카테고리마다 동일 구매가 포함될 수 있어 카테고리 건수의 합계를 전체 구매 건수로 쓰지 않는다. 0원 배분행은 분류/건수를 불필요하게 늘리지 않도록 합친 결과에서 제외하며 전액 0원 거래에는 배분 하나를 보존한다.

취소 전 구매 평균은 해당 카테고리의 양수 구매 배분액 ÷ 해당 배분이 있는 원구매 수를 원 단위 반올림한다. 환불·수수료는 평균 분모에서 제외한다. 구매가 없으면 평균은 null이다. 전체 취소로 순액이 0이어도 과거 구매 사실·취소 전 평균을 지우지 않는다. 부분 환불의 용도는 사용자 확인/미분류 정책을 따른다.

비중은 **확보한 유효 거래 순액**을 분모로 하는 basis points다. 분모가 양수이고 음수 카테고리·미확인·정정 후보가 없을 때만 계산한다. 이 비중이 전체 월 소비 비중이라는 뜻은 아니다. 소수점 두 자리 아래는 버려 표시 합계에 반올림 차이가 있을 수 있다. 순액 0/음수 또는 음수 카테고리·불명 원천이 있으면 비중을 보류한다.

관측 절대 증감은 두 달의 유효 기록이 있고 미확인/정정 후보가 없을 때만 계산한다. 전월 관측 카테고리액이 양수일 때만 변화율을 제공한다. 0분모/음수 분모는 변화율 null이다. 전월 자료 없음과 확보된 거래 내 해당 분류 0을 구별한다. 6개월 추이는 빈 달을 0으로 채우지 않고, 사용자 보정 후 과거 월도 현재 revision으로 재계산한다. 이미 본 리뷰의 고정 snapshot을 보존하는 기능은 아니다. 응답에 계산 시각·버전·보정 revision이 있고 화면은 기준 확인 시각과 재계산 정책을 표시한다.

반복·일회성은 안정된 근거가 없으면 unknown이다. 같은 가맹점·할부 회차만으로 고정 소비를 추론하지 않는다. 사용자가 등록하는 예정 지출·실제 거래 연결은 PIN-62가 소유한다. unknown을 0원 또는 일회성 확정으로 표시하지 않는다.

## 계약·보안·운영 경계

`GET /api/finance/business/analysis?month=YYYY-MM`은 PIN-59 분류 readback과 공유 pure model을 사용한다. Web은 서버 수치를 재계산하지 않고 표시/정렬한다. category별 가맹점 금액·원거래 수·거래 목록, 추이는 같은 서버 배분을 사용한다. API/MSW의 의미를 맞추고 approved·owner·expected actor·no-store·owner/epoch/month cache 경계를 유지한다. 관리자도 타인 자료를 조회하지 못한다. 수정 command 성공 시 review/analysis query를 취소·무효화해 다음 진입에서 재계산한다.

수기 규칙/AI 모델·전 계좌 소비·완전한 월의 비중을 추가하지 않는다. 실파일 추가 전송은 사용자 결정으로 제외하며 합성 자료로 검증한다. 구현·자동/모바일 dev 검증·정리 결과는 [PIN-61](https://linear.app/pin-dev/issue/PIN-61)이 소유한다.
